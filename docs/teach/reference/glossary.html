Глоссарий: OAuth, PKCE, Supabase Auth

Одна страница, к которой возвращаешься. Термины употребляются во всех уроках именно в этом значении — если в уроке слово звучит иначе, ошибка в уроке.

1 Роли и участники

Термин Значение
Resource Owner Человек. Тот, кто владеет аккаунтом у провайдера и даёт согласие. В anihive — пользователь, который жмёт «Войти через Google».
Client Приложение, которое хочет узнать, кто этот человек. Внимание: в связке с Supabase client — это сам Supabase, а не anihive. Google знает Supabase, про anihive он не слышал.
Authorization Server Тот, кто аутентифицирует человека и выдаёт код/токены. Google (accounts.google.com) на внешнем слое; сам Supabase (/auth/v1) на внутреннем слое — он тоже authorization server для твоего приложения.
Provider Слово Supabase для внешнего authorization server: google, discord, github. Значение Provider — это union-тип в @supabase/supabase-js.
GoTrue Историческое (и до сих пор живое в коде) имя auth-сервера Supabase. Go-сервис в репозитории supabase/auth. Отсюда класс GoTrueClient внутри @supabase/auth-js.

2 Механика OAuth 2.0 и PKCE

Термин Значение
Authorization Code
code		 Одноразовый короткоживущий талон в query-параметре redirect-а. Сам по себе не даёт доступа: его нужно обменять на токены. Ходит через адресную строку — то есть через историю браузера, логи прокси и Referer. Поэтому и нужен PKCE.
Authorization Code Grant Флоу «редирект → code → обмен на токены». Единственный рекомендованный для веба вариант (RFC 9700).
Implicit Flow Устаревший флоу: токены приходят прямо в URL-фрагменте (#access_token=…). Фрагмент не уходит на сервер — поэтому SSR его в принципе не видит. Запрещён современными best practices; в Supabase остаётся как flowType: 'implicit'.
PKCE
Proof Key for Code Exchange		 Читается «пикси». Доказательство, что код обменивает тот же, кто его запросил. Без секрета клиента: он заменён на одноразовую пару verifier/challenge (RFC 7636).
code_verifier Случайная строка (43–128 символов), которую генерирует и хранит у себя инициатор входа. Отправляется только один раз — в момент обмена кода. Украденный code без верификатора бесполезен.
code_challenge base64url(sha256(code_verifier)) без padding. Уходит открыто в ссылке на authorization server. Из него нельзя восстановить verifier — вся суть.
code_challenge_method S256 — нормальный вариант. plain — fallback, если в среде нет SHA-256 (в браузере не случается). Проверку смотри в internal/security/pkce.go.
state Непрозрачное значение, которое authorization server возвращает как есть. Защита от CSRF и способ «запомнить контекст». В Supabase роль state играет id записи flow_state.
redirect_uri Куда authorization server отправит браузер с кодом. Должен быть заранее зарегистрирован и сверяется побайтово. Отсюда redirect_uri_mismatch.
scope Запрашиваемый объём доступа (email, profile, guilds…). Больше scope — страшнее экран согласия и хуже конверсия. Проси минимум.
Consent screen Экран «приложение X хочет доступ к…». Показывается человеку, а не твоему коду; выглядит как Supabase-проект, потому что client — Supabase (см. выше).

3 OpenID Connect: слой identity

Термин Значение
OIDC Тонкий слой поверх OAuth 2.0, который добавляет «кто это» к «что можно». Google его реализует, Discord — нет. Поэтому Google отдаёт id_token, а данные Discord Supabase дочитывает отдельным запросом к его API.
id_token Подписанный JWT о личности: sub, email, email_verified, aud, exp. Проверяется по публичным ключам провайдера. Не путать с access token — id_token отвечает «кто», а не «что можно».
nonce Одноразовое значение, вшиваемое в id_token для защиты от replay. Не то же, что state: state защищает редирект, nonce — сам токен.
sub Стабильный идентификатор человека у провайдера. Именно он ложится в auth.identities.provider_id — email меняется, sub нет. Матчить пользователя по email — ошибка проектирования.

4 Термины Supabase Auth

Термин Значение
Session Пара «access_token (JWT, ~1 час) + refresh_token (долгий, одноразовый)» плюс объект user. В SSR-режиме лежит в cookie, не в localStorage.
Access token / JWT Подписанный Supabase токен, который читает Postgres в RLS-политиках (auth.uid()). Это твой токен, не токен Google.
provider_token / provider_refresh_token Токены Google/Discord, приходящие в объекте session один раз после входа. Нужны только чтобы ходить в API провайдера. Supabase их не хранит — не сохранишь сам, потеряешь.
flow_state Строка в таблице auth.flow_state: code_challenge, провайдер, referrer, срок жизни. Живёт между «начали вход» и «обменяли код». Истекла или уже использована — получаешь invalid flow state.
identity Строка в auth.identities: связка «пользователь ↔ провайдер ↔ sub». У одного auth.users может быть несколько identity: пароль, Google, Discord.
Identity linking Присоединение ещё одного провайдера к существующему пользователю. Автоматически — только если email у провайдера подтверждён и совпадает (и включено в настройках). Иначе — вручную через linkIdentity.
Site URL Настройка проекта: куда редиректить, если redirectTo не передан или не прошёл allow list. Классический симптом опечатки: тебя выкидывает на localhost:3000 с прода.
Redirect allow list Список разрешённых redirectTo в настройках проекта (поддерживает *). Не путать с authorized redirect URI в Google Cloud — это разные списки на разных слоях.
storageKey Префикс ключей auth-клиента: sb-<project-ref>-auth-token. Отсюда имена cookie, включая …-auth-token-code-verifier и чанки ….0, ….1.
Cookie chunking Сессия больше ~3.6 КБ режется @supabase/ssr на несколько cookie с суффиксами .0, .1. Вручную такие cookie не читать — только через клиент.

5 Термины этого проекта

Термин Значение
src/proxy.ts Middleware в терминах Next.js 16. Делает две вещи: обновляет сессию (updateSession) и охраняет роуты по PROTECTED_PAGES / NON_AUTH_ONLY_PAGES.
browser / server / proxy client Три фабрики в src/shared/api/supabase/. Разные способы добраться до cookie: document.cookie, cookies() из next/headers, объекты NextRequest/NextResponse.
{ error: string | null } Контракт всех auth-функций в проекте: наружу отдаётся строка, а не объект ошибки Supabase. Новый OAuth-код обязан его соблюдать.
