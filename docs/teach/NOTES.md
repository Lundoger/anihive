## Что известно про проект (контекст для уроков)
- Next.js 16.3.1, middleware называется `src/proxy.ts` (не `middleware.ts`).
- FSD: `src/_pages`, `src/entities`, `src/features`, `src/shared`, `src/widgets`.
- Сессия: zustand-стор `src/entities/session/model/store.ts` + `useSessionSync` на `onAuthStateChange`.
- Server actions в `src/entities/session/api/index.ts`, браузерные вызовы в `authClient.ts` — разделение осознанное.
- Все auth-функции возвращают `{ error: string | null }`, наружу не утекает объект ошибки Supabase. **Сохранять этот контракт в новом коде.**
- env-ключ называется `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY` (не `ANON_KEY`).
- i18n: `localePrefix: "as-needed"`, локали `ua`/`en`, default `en`.

## Как подавать материал (уточнено после урока 1)
- **Абстрактных контрактов недостаточно.** На «вот сигнатура, напиши тело» Богдан застревает: не хватает
  опоры на конкретику. Работает связка: точный тип → *реальные значения* с примером → структура файлов
  таблицей → и только потом «пиши тело».
- Показывать значения, а не только типы: как выглядит объект `result`, какая строка в `url`, что внутри
  `session`. Отсюда родился `reference/api-shapes.html`.
- Разбор *его собственного черновика* заходит лучше любого абстрактного примера — просить показывать
  недоделанный код раньше, а не ждать «готово».
