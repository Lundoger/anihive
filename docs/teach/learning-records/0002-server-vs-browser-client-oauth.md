# Выбор клиента для старта OAuth: браузерный vs серверный

Богдан в первом черновике `features/oauth/index.ts` взял серверный клиент
(`@/shared/api/supabase/server`) для `signInWithOAuth` — разумная догадка по аналогии с `serverSignIn`,
которая не работает по неочевидной причине: `_handleProviderSignIn` не делает сетевых запросов, он строит
URL и полагается на `window.location.assign`, а на сервере `isBrowser()` ложно, поэтому редирект просто
не происходит и `data.url` теряется.

**Почему важно:** это не «ошибка синтаксиса», а разрыв в модели — предположение, что вход через провайдера
работает как обычный вызов API (запрос → ответ), тогда как это *навигация браузера*. Пока эта модель не
встала на место, ловушки с `redirectTo`, cookie верификатора и route handler будут выглядеть случайными
правилами.

**Implications:** урок 2 (внутренности обмена кода) должен начинаться не с базы и токенов, а с фразы
«кто инициирует каждый HTTP-запрос в этом флоу». Также проверить на Discord: если он снова возьмёт серверный
клиент по инерции — модель не закрепилась.
